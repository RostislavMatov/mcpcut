MCP · self-hosted · Apache-2.0

A journal and an emergency brake for your AI agents

See every tool call your agent makes over MCP, hold the risky ones until you say yes, and keep a secret-redacted journal that is tamper-evident with an external anchor.

Quick start Source on GitHub

Node.js 24+ · two runtime dependencies · runs on your laptop, grows into a control plane for many agents

01 See

Every request, response and decision goes into a journal on your machine. Secrets are redacted before anything is written. Optionally fail-closed: no record, no call.

02 Stop

A policy per tool — allow, deny or require-approval. A risky call waits until you approve it from the CLI, the web UI or the terminal console. A new tool, or one whose schema changed after you trusted it, is quarantined with a diff.

03 Prove

A hash chain with a signed head. Export an audit report and verify it offline with a public key. Record the chain head somewhere this host cannot rewrite: the journal is tamper-evident with an external anchor, not by its hashes alone.

Quick start

Node.js 24+, nothing else to install

See

Put mcpcut in front of a server — here for Claude Code. In any other client, the server's command becomes npx -y mcpcut@0.2.2 wrap -- <your server>.

claude mcp add fs -- npx -y mcpcut@0.2.2 wrap -- npx -y @modelcontextprotocol/server-filesystem ~/project

Let the agent work, then read what happened — every request, response and decision, secrets redacted:

npx -y mcpcut@0.2.2 sessions
npx -y mcpcut@0.2.2 show <id>

Stop

Save this as policy.json and re-add the server with --policy "$PWD/policy.json" right after wrap: reads pass, everything else waits for you.

{ "version": 1, "defaultDecision": "require-approval", "classDefaults": { "read": "allow" },
  "quarantine": { "enabled": false } }

A write now waits. Approve it from another terminal within the agent's wait:

npx -y mcpcut@0.2.2 approvals list
npx -y mcpcut@0.2.2 approvals approve <id>

Prove

Sign the history, export it, and check it offline — with nothing but the directory:

npx -y mcpcut@0.2.2 keygen && npx -y mcpcut@0.2.2 export --report --out ./report
npx -y mcpcut@0.2.2 verify --report ./report

The full walkthrough, with what each step prints: README · Quick start.

Grow into a control plane

one install, many agents 
npm install -g mcpcut

Then run mcpcut: a setup wizard, and after it everything a team of agents needs.

  • Agents and grants — a registry of servers, a key per agent, per-tool grants, groups, and an encrypted vault, so server credentials never sit in an agent's config.
  • One address per agent — every server an agent is granted behind one endpoint; grant or revoke without touching the client.
  • Web UI and terminal console — named admins with owner, operator and viewer roles; every change is attributed in the journal.
  • Services and Docker — start, stop and back up the service on your machine or a server of your own.

How it works

 (Claude Code,                 grants → policy →          (filesystem,
  Cursor, …)                   quarantine → approval       GitHub, …)
                                 │
                                 ▼
                     journal.db — redacted, hash-chained
                                 │  export --report
                                 ▼
                     verify offline, anywhere
  • wrap — in front of one server, with no setup and no identity: the Quick start above.
  • connect and serve — named servers from the registry, a key per agent, credentials from the vault.
  • The pool (/mcp) — one address per agent for every server it is granted.

Hosted preview

mcpcut.com

mcpcut.com is hosted in preview. Sign in with GitHub and, while seats last, you get an install of your own at <your-login>.mcpcut.com — ready in about a minute, its owner token shown once. It fronts remote MCP servers over HTTPS only; a server that runs as a local command needs your own install (the Quick start above). Seats are few: once they are taken, sign-in puts you on a waitlist. An install left idle for 60 days is stopped, and removed after 90.

What it is not

  • Not a security scanner: it does not look for prompt injection. It controls what an agent may call and keeps the evidence.
  • Not a generic gateway and not a catalogue of public servers: it sits in front of the servers you choose.
  • Not proof against its own host: a process running as the same OS user can rewrite the journal and re-sign it. Only a chain head recorded somewhere this host cannot write exposes that. Whether a report satisfies an audit is the auditor's call.
