# Roadmap — MCP Control Plane

Горизонт: MVP «ядро + admin UI» → пилоты с design-партнёрами. Оценка: **~12 недель** от старта кода (ориентир: старт середина августа 2026 → pilot-ready к началу ноября 2026). Недели — относительные, сдвигаются от фактического старта.

## Треки

Работа идёт в два параллельных трека. Кодовый трек без партнёрского не имеет смысла — валидация гипотезы требует пилотов.

### Трек A — продукт (код)

| Недели | Milestone | Содержание | Выход (gate) |
|---|---|---|---|
| 1–2 | **M1. Журналирующий прокси (stdio)** — ✅ выполнен | Прокси-обёртка `command`, framing, классификация JSON-RPC, редакция секретов, JSONL-журнал, CLI sessions/show | Реальный сервер работает через прокси в Claude Code без отличий; вся сессия в журнале; coverage ≥ 80% — **подтверждено** (327 тестов, coverage ~98%, ручная проверка на `server-memory`) |
| 3–4 | **M2. Политики и классификация** | read/write/destructive классификация тулзов, карантин новых/изменённых, allow/deny/require-approval (конфиг), блокировка на уровне вызова, фильтрация `tools/list` | **Dogfood-gate**: свои агенты работают через прокси с политиками; изменяющий вызов не проходит без правила |
| 5–7 | **M3. Реестр + учётки + вольт + HTTP** | Реестр MCP-серверов, вольт учёток (секреты не в конфигах агентов), учётки агентов × матрица прав, виртуальные серверы per-agent (неймспейсинг тулзов), streamable HTTP транспорт | Онбординг нового агента < 10 мин; ключи только в вольте; отзыв доступа в одно действие |
| 6–9 | **M4. Admin UI + очередь одобрений** (частично параллельно M3) | Веб-UI: реестр, матрица прав, очередь одобрений с уведомлениями, просмотр/поиск журнала | Человек одобряет/отклоняет write-операции из UI в пределах клиентского таймаута |
| 9–10 | **M5. Доказательный журнал** | Tamper-evident подпись записей (hash-chain/HMAC), шифрование at rest, retention, экспорт аудит-отчёта | **Pilot-ready gate**: отчёт по сессии, который можно показать аудитору партнёра |
| 11–12+ | **M6. Пилоты** | Развёртывание у 2–3 партнёров, инструкции self-hosted установки, сбор обратной связи, итерации | Гипотеза PRD: ≥1 аудит-отчёт принят аудитором партнёра |

### Технический бэклог из ревью M1 (решить в рамках M2/M5)

Осознанно отложенные находки ревью (все CRITICAL/HIGH и большинство MEDIUM/LOW закрыты в M1):

- **Политика fail-open журнала** (M2): при постоянных ошибках записи прокси продолжает ретранслировать без журнала и выходит с кодом 0. Для enterprise-сегмента нужен конфигурируемый fail-closed (убить child, ненулевой код) + счётчик потерянных записей.
- **Child имеет write-доступ к своему журналу** (M5): дочерний процесс работает под тем же uid и может переписать `~/.mcp-journal/*.jsonl`. До hash-chain (M5) журнал не tamper-evident; варианты — отдельный uid писателя, append-only атрибут, отгрузка off-box.
- **JSON-RPC batch** классифицируется как `invalid` (осознанно, зафиксировано тестом) — пересмотреть при переходе на спеку 2026-07-28.
- Мелкое: shallow `Object.freeze` записей (payload мутабелен), UTF-8-разрыв на границе overflow-флаша (достижим только через capped-путь).

### Трек B — валидация и рынок (без кода, параллельно с недели 1)

| Недели | Действие | Зачем |
|---|---|---|
| 1–8 | Поиск 2–3 design-партнёров (нетворк, MCP-комьюнити, compliance-команды) | Критический блокер M6; PRD: искать параллельно M1, не после |
| 4–8 | Интервью с практикующим аудитором (EU AI Act Art. 12 / SOC 2): какой формат отчёта примут | Определяет требования M5 до его начала — экономит переделки |
| 1–12 | Публичность: README, лендинг/пост, open-core решение (что открываем) | Дистрибуция в enterprise через инженеров; окно ниши сужается (M&A: Invariant→Snyk) |

## Контрольные точки и решения

| Когда | Checkpoint | Решение |
|---|---|---|
| Конец недели 2 (после M1) | Смок на реальных клиентах (Claude Code, Cursor) | Если approval не укладывается в таймауты клиентов — пересмотр механики M2 (async-одобрения/`tasks`) |
| Конец недели 4 (dogfood-gate) | Собственные агенты живут через прокси ≥ 1 неделю | Если approval fatigue невыносим — политики-исключения до M4 |
| ~Октябрь 2026 | Финализация спеки MCP 2026-07-28 (+10 недель валидации) | Решить: поддержка старой+новой модели или только новой; затрагивает M3 (HTTP/сессии) |
| Конец недели 8 | Есть ли хотя бы 1 подтверждённый design-партнёр? | **Нет → пивот-решение**: сегмент команд разработки (self-hosted, дешевле) вместо enterprise |
| Конец недели 10 (pilot-ready gate) | Ревью: security-аудит своего же продукта (`/ecc:security-scan`, `ecc:security-reviewer`) | Продукт, хранящий чужие секреты, не выходит к партнёрам без аудита |

## После MVP (не планируем детально до валидации)

SSO/SAML + RBAC админов → retention-политики под конкретных регуляторов → каталог публичных MCP → SaaS-версия → replay-режим. Порядок определит обратная связь пилотов.
