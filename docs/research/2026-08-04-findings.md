# Исследование: рынок, OSS-ландшафт, техосуществимость (2026-08-04)

Сводка трёх параллельных исследований (рынок / open source / техническая часть), проведённых до написания PRD. Полные выводы сжаты до того, что влияет на решения.

## 1. Рынок

- **Зрелость**: растущий, но сегмент «MCP security gateway» быстро переполняется — Lasso Security (MCP Secure Gateway, Gartner Cool Vendor), Stacklok/Toolhive ($17.5M Series A), MintMCP, MCP Manager (Usercentrics), Pomerium, Arcade.dev, Traefik Hub, Lunar.dev. Все появились в 2025–2026 почти одновременно, явного лидера нет.
- **Консолидация началась**: Invariant Labs (mcp-scan) куплен Snyk. Gartner: к концу 2026 у 75% вендоров API-гейтвеев будут MCP-фичи → базовое логирование комодитизируется.
- **LLM-observability платформы** (Langfuse, LangSmith, Helicone, Arize, Datadog, New Relic) видят MCP-вызовы только как generic tool-call spans — протокол-специфичного трейсинга (handshake, schema drift, silent tool skip) нет ни у кого.
- **Кто платит**: developer-сегмент НЕ платит (полно бесплатных OSS). Платит enterprise/compliance: цены конкурентов от $25K/год. Драйверы: EU AI Act Article 12 (автологирование, tamper-evident, retention 6–24 мес; дедлайн high-risk перенесён на 12.2027/08.2028), SOC 2 Type II, procurement-вопрос «может ли аудитор воспроизвести действие агента 18 месяцев спустя».
- **Adoption MCP**: SDK ~2M → 97M monthly downloads за 16 мес (+4750%); 9400+ публичных серверов; remote deployment +400% с мая 2025; протокол передан в AAIF (Linux Foundation, соучредители Anthropic/Block/OpenAI) — риск смерти стандарта низкий.

## 2. Open-source ландшафт

**Переполнено**: multi-server гейтвеи (IBM mcp-context-forge 4.2k★, Docker MCP Gateway, Toolhive), статические security-сканеры (mcp-scan 2.8k★, Cisco, NVIDIA, Snyk), транспортные мосты (sparfenyuk/mcp-proxy 2.7k★, supergateway 2.8k★).

**Недоразвито (наша ниша)**: production-grade персистентный аудит-журнал как продукт; поиск по истории сессий; tamper-evident подписи (есть только у молодых/сырых obsigna, SousMCP, mcp-audit); merge мульти-сессий, retention/ротация; UX «что агент реально сделал».

**Ни один проект не даёт одновременно**: (а) перехват реального трафика, (б) структурированное хранилище с поиском, (в) tamper-evidence, (г) все транспорты + UI. Каждый берёт 1–2 оси из четырёх.

**Ближайшие конкуренты/референсы**:
- `kerlenton/mcpsnoop` (324★, Go) — «Wireshark for MCP»: сидит в реальном пайпе, JSONL, baseline/diff дрейфа тулов, экспорт HAR/OTLP
- `fiberplane/mcp-gateway` (23★, TS) — SQLite-журнал + React dashboard из коробки, компактная кодовая база
- `P4ST4S/mcp-audit` (Go) — схема записи: ULID, direction, redacted params, duration, HMAC-подпись, JSONL/SQLite — референс схемы журнала
- `devhelmhq/mcp-recorder` — record/replay/verify с cassette-форматом (replay у нас out of scope, но формат — референс)
- roadmap MCP 2026 сам признаёт audit trails / operational visibility недоразвитой зоной

## 3. Техническая часть

- **Перехват**: подмена `command` (stdio) / `url` (HTTP) в конфиге клиента (`.mcp.json`, `claude_desktop_config.json`). MITM-сертификаты не нужны. stdio: прокси порождает реальный сервер и ретранслирует stdin/stdout построчно; спека требует «MUST NOT contain embedded newlines» — баг фрейминга ломает протокол целиком.
- **Готовые блоки**: TS SDK — `Transport.onmessage/onclose/onerror`, `InMemoryTransport` для тестов; Python — `FastMCP.as_proxy` (полный прокси с sampling/elicitation из коробки).
- **Клиенты нативно**: Claude Code НЕ пишет персистентный MCP-лог (открыт anthropics/claude-code#29035 — просят parity с Claude Desktop) — одновременно обоснование ценности и риск, что Anthropic закроет сам. Claude Code: таймауты (`MCP_TIMEOUT`), обрезка вывода тулзов (25k токенов дефолт), автореконнект HTTP, вызовы >2 мин → background. Эти метасигналы журнал должен фиксировать.
- **Захват**: все категории JSON-RPC — requests, responses, notifications, server-initiated (`sampling/createMessage`, `elicitation/create`, `roots/list`). Не полагаться на `notifications/message` сервера — захватывать сырой трафик.
- **Корреляция**: stdio — процесс = сессия; HTTP — заголовок `MCP-Session-Id` + JSON-RPC id; для сквозного трейса есть паттерн инжекта `traceparent` в `params._meta` (mcp-otel-proxy).
- **Хранение**: JSONL append в реальном времени (не блокирует критический путь) + асинхронный индекс в SQLite для UI/поиска.
- **Протокольный риск (главный)**: RC-спека **2026-07-28** — stateless: убирает `initialize` handshake и `Mcp-Session-Id`; SEP-2322 заменяет server-initiated requests на `InputRequiredResult`+`requestState` (клиент пересылает вызов с `inputResponses`). Финал: 28.07.2026 + 10 недель валидации. Также история: 2025-03 Streamable HTTP заменил SSE; 2025-06 OAuth Resource Servers + RFC 8707; 2025-11 OIDC Discovery, tasks. → транспорт отделять от семантики.
- **Оценка усилий**: MVP journaling-прокси 3–5 недель; production-grade (подписи, SQLite-индекс, OTel, новая спека, UI) 8–12 недель.

## Выводы, вшитые в PRD

1. Позиционирование: «контроль доступа агентов + доказательный журнал», не security-детекция и не generic gateway.
2. Дифференциатор: per-agent учётки × per-tool права × human-in-the-loop на write × tamper-evident журнал — комбинация, которой нет ни у кого в зрелом виде.
3. E2E-шифрование payload несовместимо с инспекцией — осознанный отказ; шифруем хранилище и транзит.
4. Классификация read/write: аннотации `readOnlyHint`/`destructiveHint` — недоверенные hints; нужна эвристика + карантин новых/изменённых тулзов (защита от rug pull).
5. Approval-окно ограничено клиентскими таймаутами — проверить на реальных клиентах (открытый вопрос PRD).
