# Смок: мост `mcpcut connect --url` (ADR-0015, фаза 2 PRD «пул агента»)

Дата: 2026-09-21. Ветка рабочего дерева `feat/agent-pool-core` (параллельная сессия фазы 1 создала её
и перенесла туда незакоммиченную работу фазы 2 — см. «Открытые вопросы»). Сборка `npm run build`.

## Стенд

- **Сервис**: `mcpcut serve --port 18990` над скретч-каталогом данных
  (`MCPCUT_DATA_DIR=<scratch>/smoke/data`, `MCPCUT_CONFIG=/nonexistent/x.json`), политика
  `defaultDecision: allow`, карантин выключен. В реестре один stdio-сервер `demo`
  (`tests/fixtures/policy-server.mjs`, тулзы `echo`, `risky_tool`, `special_tool`), владелец `op`,
  агенты `bot`/`bot3` с грантом `*` на `demo`.
- **Клиент**: `node dist/cli.js connect --url …` дочерним процессом с окружением
  **`{PATH, MCP_AGENT_TOKEN, HOME: /nonexistent-home}`** — ни каталога данных, ни `config.json`, ни
  реестра. Это и есть проверяемое утверждение фазы 2.
- Драйвер (`drive.mjs`): пишет `initialize` → `notifications/initialized` → `tools/list` →
  `tools/call`, каждую строку после ответа на предыдущую, затем закрывает stdin.

## Ответ на открытый вопрос PRD: какую модель сессии говорит клиент

Драйвер послал `initialize` с `protocolVersion: "2025-06-18"`. На стороне сервиса
(`mcpcut sessions` → `mcpcut show <id>`) видно:

- фронт открыл **sessionful**-сессию: выдал `Mcp-Session-Id`, завёл журнальную сессию
  `01M30CAB23QBV3QY39QFRXWFPM`, в конце записал `[serve] bot/demo: session … ended (closed)`;
- HTTP-клиент моста определил модель транспортно (по наличию заголовка в ответе на первый POST) и
  открыл серверный GET-поток — это и подтверждается косвенно тем, что остановка `serve` обрывает
  именно поток (пункт 7);
- **сервер ответил `protocolVersion: "2026-07-28"`** — фикстура отвечает своей версией, то есть на
  этом стенде версии клиента и сервера разошлись, и плоскость это пропустила как есть (она не
  переводит между моделями, ADR-0002).

Практический вывод для фазы 3: адрес пула должен обслуживать **sessionful**-модель — это то, что
говорит клиент через мост сегодня. Зеркальные заголовки `Mcp-Method`/`Mcp-Name` мост шлёт всегда
(`perMessageHeadersOptionOf('auto')`), поэтому stateless-фронт тоже не ответит `-32020`.

Список `SESSIONFUL_PROTOCOL_VERSIONS` из плана фазы 1 правкой по итогам смока **не нуждается**: клиент
запросил `2025-06-18`, версию из уже поддерживаемого сессионного ряда.

## Что НЕ прогонялось

- **Живой MCP-клиент** (Claude Code, Cursor, MCP Inspector) через `.mcp.json`. Прогон драйвером
  воспроизводит ту же последовательность байт, но не отвечает на вопрос, как клиент показывает
  пользователю ошибку `-32004` и код выхода 4. Пункт 2 выше отвечает на вопрос PRD о модели сессии
  через **наш** драйвер; вторым клиентом это не перепроверено.
- Мост за настоящим TLS и за обратным прокси (таймауты долгого `tools/call` с одобрением человеком).
- Мост из контейнера.
- Восстановление после кратковременного падения `serve` с последующим подъёмом: остановка сервиса
  завершает мост кодом 4 (пункт 7) — что и задумано, клиент поднимет новый мост, — поэтому сценарий
  «упал и через 30 с встал, мост пережил» **не выполняется по построению** и не проверялся.
