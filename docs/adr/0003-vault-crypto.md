# ADR-0003: Крипто вольта — AES-256-GCM, мастер-ключ файлом рядом, честная модель угроз

- **Статус**: принято (2026-08-05, Волна 0 M3)
- **Область**: `src/vault/*` — хранилище секретов MCP-серверов (`vault.enc` + `vault.key`
  в `~/.mcp-journal/`)

## Контекст

M3 вводит реестр серверов; их секреты (`GITHUB_TOKEN` и т.п.) обязаны жить только в контрольной
плоскости: не в конфигах агентов, не в `registry.json` (там только ссылки `vault:<name>`), не в
журнале. SOC 2 / procurement ждут «encryption at rest». Продукт self-hosted и portable: нельзя
привязываться к облачному KMS или OS-специфичному keychain. Новых зависимостей не добавляем
(ADR-0001), TLS/крипто — только `node:crypto`.

## Решение

1. **Шифр**: AES-256-GCM (`node:crypto`, `createCipheriv`/`createDecipheriv`).
   AEAD: конфиденциальность + целостность одним примитивом, аппаратное ускорение, FIPS-совместим —
   аргумент для compliance-сегмента.
2. **Формат `vault.enc`** (права 0600): JSON-конверт `{v: 1, iv, tag, data}` — base64-поля;
   `data` — шифртекст цельного JSON `{name: value}`. Поле `v` — версия формата для будущих миграций.
3. **IV**: 12 байт из `randomBytes` на **каждую** запись файла; повторное использование IV с тем же
   ключом недопустимо (GCM ломается катастрофически) — тест-гарантия «две записи → разные IV».
4. **AAD**: версия формата подмешивается как associated data — конверт нельзя пересобрать с чужим `v`.
5. **Мастер-ключ**: 32 байта `randomBytes` в `vault.key` (0600, создаёт `vault init`; отказ, если
   файл существует). Ключ и данные — раздельные файлы: бэкап/синк каталога данных без `vault.key`
   бесполезен атакующему; инструкция README — исключать `vault.key` из бэкапов.
6. **Битый tag** (повреждение/подмена/чужой ключ) → именованная ошибка `VaultIntegrityError`
   с внятным текстом; никогда не «пустой вольт» (fail-closed, гарантируется hardening-тестом).
7. **Ротация**: `vault rekey` — расшифровать текущим ключом, перешифровать новым, атомарная замена
   обоих файлов (tmp + rename, паттерн `createJsonStore`).
8. **Обращение со значениями**: расшифровка только в памяти на время резолва `vault:<name>` →
   env/заголовок upstream-процесса; значения не логируются, не печатаются CLI (`vault list` — имена
   и даты), в журнале режутся редакцией (маркер-тест через все носители). `vault set` читает значение
   со stdin/prompt — не из argv (argv виден в `ps`).

## Модель угроз — честно

**Защищает от**:
- утечки файлов данных: бэкапы, синк дотфайлов, копирование `~/.mcp-journal/`, снапшоты диска —
  без `vault.key` содержимое `vault.enc` криптостойко;
- случайного раскрытия: секреты не лежат плейнтекстом в registry/журнале/конфигах агентов,
  `grep`-утечки невозможны;
- тихой подмены хранилища (integrity: GCM-tag + AAD).

**НЕ защищает от**:
- **компрометации хоста / того же uid**: атакующий, читающий файлы пользователя, читает и `vault.key`
  рядом с `vault.enc` и расшифровывает всё. Это та же граница доверия, что и у остальных сторов
  (`policy.json`, `agents.json`, сам процесс плоскости с секретами в памяти) — ключ рядом с данными
  не понижает её, но и не повышает. Смягчение «отдельный uid для плоскости и сторов» — бэклог
  (перенос из M2);
- root/отладчика/дампа памяти работающего процесса;
- вредоносного MCP-сервера, которому секрет легитимно выдан в env — это закрывается не вольтом,
  а грантами (агент видит только выданное) и журналом.

Формулировка для README/аудитора: «шифрование at rest закрывает канал утечки через копии файлов;
границей доверия остаётся учётная запись ОС, под которой работает плоскость».

## Альтернативы

| Вариант | Почему нет |
|---|---|
| OS keychain (Keychain/DPAPI/libsecret) | Не portable для self-hosted (Linux-серверы headless, Docker); три платформенных бэкенда + зависимость; недоступен из systemd-юнитов без танцев |
| Внешний KMS (AWS/GCP/Vault by HashiCorp) | Не для MVP: тянет облачную зависимость в self-hosted продукт, онбординг ломает метрику «10 минут»; правильный enterprise-путь позже — плагин-интерфейс поверх того же `resolve.ts` (бэклог) |
| Пассфраза вместо ключ-файла (scrypt/argon2) | Интерактивный ввод убивает автозапуск (`serve` как сервис); argon2 — новая зависимость; можно добавить как опцию поверх (ключ, зашифрованный пассфразой) — бэклог |
| age/libsodium | Новая зависимость ради того, что `node:crypto` даёт из коробки (ADR-0001) |
| Плейнтекст + права 0600 | Не проходит «encryption at rest» (SOC 2), не закрывает бэкап-канал |

## Последствия

- (+) Ноль зависимостей, portable, аудируемый формат в ~100 строк кода; SOC 2-требование закрыто
  с честной оговоркой о границе доверия.
- (−) `vault.key` — единая точка: потеря = потеря секретов (README: ключ бэкапится отдельно от
  данных); кража uid = кража вольта (задокументировано, смягчение в бэклоге).
- Security-ревью `ecc:security-reviewer` по `vault/*` обязательно (Task 15); hardening-тесты:
  битый tag, повторный IV, права файлов, отсутствие значения во всех выводах.
