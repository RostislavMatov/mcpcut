# ADR-0014: Удалённая консоль — `mcpcut --remote <url>` поверх HTTP-эндпоинта `ui`

- **Статус**: принято (2026-09-19, решения владельца RC1–RC4)
- **Область**: контракт `src/console-api/contract.ts`; маршруты `/api/console/*`
  (`src/ui/console-api.ts`, `src/ui/console-run.ts`, ветка в `src/ui/server.ts`); исполнитель команд
  в процессе `ui` (`src/cli/console-runner.ts`); клиент `src/tui/remote/*`; вход `--remote` /
  `MCPCUT_REMOTE` (`src/cli.ts`, `src/cli/tui-cmd.ts`).
- **Поправляет**: ADR-0012 п. 19 (допущение «консоль ≡ shell под uid службы»), ADR-0004 (поверхность
  `ui` и её модель угроз).

## Контекст

Рамка владельца от 19.09: сервис разворачивается где угодно (свой ПК, Docker, VPS), первична
консоль, браузер необязателен. До этого дня рамка держалась только там, где есть shell на хосте:
консоль — локальная программа, каждое её действие — команда CLI, исполняемая `dispatch(argv)` в том
же процессе над базами на локальном диске. С удалённым сервисом оставались веб-админка либо
`ssh -t host mcpcut`.

Владелец попросил третий путь: поставить у себя «только оболочку», указать адрес сервиса и работать.

То, что консоль — тонкий слой над одной внедряемой функцией `DispatchFn(argv, io, options)`, делает
это дешёвым: удалённый режим подменяет эту функцию (и резолвер сеанса), а каталог из 12 разделов,
формы, живая очередь и запись `export` в локальный файл остаются тем же кодом.

## Решения владельца

| # | Вопрос | Решение | Отклонено |
|---|---|---|---|
| RC1 | Транспорт | HTTP-эндпоинт на `ui`, тот же порт, Bearer-токен админа | обёртка над SSH; «ничего не строить, `ssh -t`» |
| RC2 | Охват | всё, что умеет консоль | только плоскость управления без хост-операций |
| RC3 | Первый владелец по сети | код из `<data dir>/setup-code` + имя | только сообщение «зайдите на хост» |
| RC4 | Запись в вольт по сети | только по https или loopback | никогда; всегда с предупреждением |

## Решение

1. **Контракт — четыре запроса.** `GET state` (публичный: есть ли хоть один админ), `POST whoami`
   (токен → имя и роль), `POST setup` (код + имя → первый владелец и его токен, один раз),
   `POST run` (`argv` и, для `vault set`, секрет отдельным полем → NDJSON-поток кадров
   `out`/`err` и ровно один завершающий `exit`). Поток без `exit` — исход неизвестен, клиент
   показывает его как неудачу и никогда как код 0. Обе стороны валидируют одними zod-схемами.

2. **Сеанса на сервере нет, и клиент не спрашивает «жив ли токен» отдельным запросом.** Локальная
   консоль перепроверяет сеанс перед каждой командой чтением стора; по сети та же проверка была бы
   вторым запросом на каждое действие, а любой сетевой сбой читался бы как «токен отозван» и
   выбрасывал оператора на экран входа (HIGH TS-ревью). Команду аутентифицирует сам `run`: сетевой
   сбой — неудачный запуск в панели, сеанс цел; ответ `unauthorized` — следующий же эффект
   возвращает на экран входа. Токен админа едет в `Authorization: Bearer` каждым запросом и
   разрешается тем же поиском в сторе, что вход в веб и `MCP_ADMIN_TOKEN` у CLI; ротация или
   удаление админа действует на следующий же запрос. У клиента токен живёт в той же `TokenCell`,
   что и локально: не в модели, не в argv, не на кадре; адрес сервиса токена не содержит и нигде,
   кроме флага/переменной, не хранится.

3. **Браузер — не клиент этого API.** Любой запрос под `/api/console/` с заголовком `Origin`
   получает 403, cookie не читаются. Это и есть вся CSRF-защита: страница злоумышленника не может
   ни отправить запрос без `Origin`, ни приложить токен, которого у неё нет. Host-валидация
   (DNS-rebinding) — общая со всем `ui`. Правило «POST без `Origin` → 403» для остальных маршрутов
   не тронуто.

4. **Отказы и перебор.** Bearer-токен — тот же секрет, что принимает `/login`, поэтому угадывать
   его здесь стоит столько же: общий с `/login` и `/setup` keyed rate-limit со счётом до первого
   `await`, тот же глобальный штраф-задержка под общим `penaltyGate` (HIGH security-ревью: без него
   API был бы дешёвой дверью для распределённого перебора), единый байт-идентичный 401. Успешный
   запрос консоли снимает свою предварительную отметку и из глобального окна — иначе штатный опрос
   очереди одобрений сам доводил бы установку до штрафа.

5. **Пол ролей по сети (поправка ADR-0012 п. 19).** Допущение «кто запустил консоль, тот уже имеет
   shell под uid службы» по сети ложно, и ADR-0012 заранее назвал, что тогда делать. Сервер держит
   таблицу минимальной роли по первому слову argv — она действует *поверх* собственных гейтов
   команд: хост-операции без своего гейта (`keygen`, `backup`, `migrate`, `verify`, `prune`,
   `start`, `stop`, `logs`), весь `vault` (у `vault init|list` своего гейта нет, а веб показывает
   имена секретов только `owner`) и `export --report|--out` (пишет каталог на диск сервера —
   по природе это `backup <dir>`) — `owner`; потоковый `export` и любая форма `policy`, кроме
   голого `policy show`, — `operator`; остальное чтение — `viewer`. Правило для `policy` записано
   как разрешение ОДНОЙ формы, а не запрет известных флагов: `policy show --policy <путь>` без
   гейта читал бы произвольный файл сервера под `viewer` (HIGH security-ревью), и флаг,
   добавленный позже, не должен стать новой дырой. Локальная консоль не меняется: там допущение
   п. 19 по-прежнему верно.

6. **Allowlist, а не denylist.** Исполняются только команды каталога консоли. `tui`, `ui`, `serve`,
   `wrap`, `connect`, `setup` и пустой argv — демоны и интерактив; в запросе-ответе им нет места.
   `Services ▸ setup` в удалённой консоли скрыт (`ActionSpec.requires`): мастер — локальный дочерний
   процесс и настроил бы не ту машину. Это единственное исключение из RC2, и оно техническое.

7. **RC2 означает: owner-токен по сети ≈ shell на сервере.** `backup <path>`, `keygen`, `stop`
   доступны владельцу удалённо. Это осознанное решение владельца; цена записана здесь, чтобы её
   не открывали заново: компрометация owner-токена теперь даёт запись на диск сервера и остановку
   служб без SSH. Смягчения: роль `owner`, https (п. 9), rate-limit, именная запись в журнале.

8. **Вольт (RC4).** `vault set|remove|rekey` исполняются, только если `ui` объявлен стоящим за TLS
   (`behindTls`) либо пир — loopback и доверенный прокси-заголовок не настроен. Иначе — отказ с
   причиной до запуска команды. Секрет `vault set` едет отдельным полем тела, попадает в
   `vault.readSecretInput` и никогда — в argv, кадры или stderr службы; без поля команда получает
   читателя, который отказывает, так что `process.stdin` демона не читает никто.

9. **Открытый http.** Как и у `--ui-public-url`: громкое `warning:` до открытия консоли и пометка на
   экране входа, не отказ. Токен админа по открытому http уже ездит при входе в веб-админку;
   консоль не вправе быть строже или мягче той же двери.

10. **Первый владелец (RC3).** Удалённая консоль над установкой без админов открывает тот же экран
    `first-owner`, но с полем кода, и вызывает `POST setup` — общее ядро с веб-`/setup`
    (rate-limit → gate → код раньше имени → CAS в сторе). Локальная консоль кода по-прежнему не
    спрашивает. Ответ переводится в ту же форму вывода, что у `admin add`, поэтому удержание
    одноразового токена (`mintsToken`) — один код на оба режима.

11. **«Только оболочка» — не отдельный пакет.** Тот же `npm i -g mcpcut`; `--remote` не требует ни
    `setup`, ни каталога данных, ни служб и обходит гейт конфига установки. Адрес не пишется в
    `~/.mcpcut/config.json`: это строгая схема *установки*, а у клиента установки нет.

12. **Вход из самого приложения (уточнение владельца, 19.09).** Голый `mcpcut` на машине без
    установки открывает экран выбора: «Set up a service on this machine» (нынешний мастер;
    `mcpcut setup` по-прежнему идёт в него сразу) или «Connect to a service on another host» — форма
    хоста, порта и протокола (`https` по умолчанию). Адрес собирается и проверяется тем же
    `parseRemoteUrl`, доступность — тем же `GET state`, не выходя из формы; успех передаёт управление
    существующему пути `--remote` (эффект `reopen`), так что удалённый вход — один код. Флаг и
    `MCPCUT_REMOTE` остаются для скриптов. Протокол не угадывается перебором `https`→`http`: тихий
    откат на открытый http был бы downgrade-атакой на токен; вместо этого отказ по `https`
    подсказывает переключить протокол.

13. **Последний адрес запоминается; отключение его забывает (решение владельца, 20.09).** Успешное
    подключение ИЗ ФОРМЫ пишет `remote.json` рядом с конфигом установки (`MCPCUT_CONFIG` двигает оба
    файла вместе): `{version, url}`, 0600, атомарно, `strictObject` — лишний ключ при чтении
    отклоняется, так что ошибка, положившая рядом секрет, не пройдёт молча. Токен не хранится никогда.
    Отдельный файл, а не поле `config.json`, по той же причине, что в п. 11: конфиг установки пишет
    `setup` целиком и правит руками оператор. Флаг `--remote` и `MCPCUT_REMOTE` файл не пишут — это
    путь скриптов. Порядок голого запуска: `--remote` > `MCPCUT_REMOTE` > локальная установка >
    сохранённый адрес > экран выбора; сохранённый адрес НЕ перебивает локальную установку.
    Недоступный сохранённый сервис открывает форму с подставленным адресом и причиной, файл цел:
    упавший сервер — не повод его забывать. Испорченный файл — одна строка `warning:` и поведение
    «файла нет». Отключение — `Home ▸ disconnect` (`requires: 'remote'`) и `Ctrl-D` на удалённых
    экранах входа и формы первого владельца (не во время `busy` и не на удержании одноразового
    токена): забывает файл и открывает `mcpcut --connect <прежний адрес>` — форму с адресом в полях.
    `--connect [url]` — и самостоятельная команда: единственный путь к форме на машине с локальной
    установкой. В шапке основного экрана удалённой консоли — `@ host:port`.

## Последствия

- Поверхность `ui` выросла на четыре маршрута, один из которых исполняет команды. Модель угроз
  ADR-0004 дополняется: нарушитель с сетевым доступом к порту `ui` и без токена получает `state`
  (один бит, который и так виден по редиректу `/login` → `/setup`) и ограниченные перебором 401.
- Команды исполняются в процессе `ui`, под его окружением (в т. ч. ключ вольта службы), а не
  дочерним процессом: тот же `dispatch`, те же гейты, те же записи журнала.
- Записи журнала удалённых действий несут `via: 'cli'` — команда не знает, что её вызвали по сети.

## Когда пересматриваем

- Понадобится отличать удалённые действия в журнале — тогда `via` получает третье значение, и это
  правка провенанса (ADR-0007), а не этого ADR.
- Появится не-консольный клиент API (скрипты, CI) — тогда контракту нужны версии и, вероятно,
  отдельные машинные токены с узкими правами вместо токена админа.
- Команды начнут жить дольше таймаутов HTTP-сервера `ui` — тогда `run` нужен отдельный таймер.
- Сохранение адреса («профили» удалённых установок) — по первому запросу, отдельным файлом рядом с
  `config.json`, не полем в нём.
