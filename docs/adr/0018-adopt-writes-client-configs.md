# ADR-0018: `mcpcut adopt` пишет в конфиги клиентов

- **Статус**: принято (2026-10-01, решение владельца «P2 и P3 в выпуске до запуска»; предложение P3)
- **Область**: `src/adopt/*`, `src/cli/adopt-cmd.ts`, `src/cli/adopt-render.ts`
- **Поправляет**: [ADR-0015](0015-agent-pool-endpoint.md) — там плоскость показывает блок конфига
  клиента, но «никогда не пишет файл клиента». Для пула агентов это остаётся так; `adopt` — отдельная
  команда для пути `wrap` на машине разработчика.

## Контекст

Первая минута по Quick start — правка конфига клиента руками на каждый сервер: `claude mcp remove`,
`claude mcp add … wrap --server <имя> -- <прежняя команда>`, на Windows ещё `cmd /c` дважды. У
разработчика на Claude Code или Cursor обычно уже есть 3–10 серверов в 2–4 файлах (`~/.claude.json` —
пользовательские и локальные, `.mcp.json` проекта, `~/.cursor/mcp.json`, конфиг Claude Desktop). Это
главное трение между «поставил» и «увидел журнал».

## Решение

1. `mcpcut adopt` находит stdio-серверы в Claude Code (user, local, project), Cursor (global,
   project) и Claude Desktop и **только показывает** изменение. Пишет — лишь `adopt --apply`.
2. Запись — поштучная: меняются только `command` и `args` записи; `env`, `type`, `cwd` и
   неизвестные ключи, порядок ключей, отступ, переводы строк, BOM и последний перевод строки файла
   сохраняются. Файл заменяется атомарно (временный файл, fsync, rename) с прежними правами; за
   симлинком пишется настоящий файл, симлинк остаётся.
3. Перед записью — копия файла в `<data-dir>/adopt/<время>/` (каталог 0700, файлы 0600: в конфигах
   лежат ключи в `env`). Файл, изменившийся между сканированием и записью (клиент сам переписывает
   `~/.claude.json`), не трогается — с просьбой повторить.
4. Не оборачиваются: удалённые серверы (`url`, `type: http|sse`) — `wrap` стоит между клиентом и
   процессом, который тот запускает; записи, уже запускающие mcpcut (`wrap` или мост `connect`); записи
   непонятной формы. Каждая названа в выводе с причиной.
5. Обёртка — `npx -y mcpcut@<версия> wrap --server <ключ записи> -- <прежняя команда>`, как в Quick
   start; на Windows — `cmd /c` перед обоими `npx` (и перед другими npm-командами и `.cmd`/`.bat`).
   Так строку целиком читает `cmd`, поэтому на Windows запись, в имени или аргументах которой есть
   `& | ^ < > % ! "` или перевод строки, не оборачивается (строка подключения с `&b=2` запустила бы
   `b=2`) — она названа в выводе, обернуть её можно руками.
6. `adopt --undo` — стек: возвращает записи последнего неотменённого `--apply`, только пока запись
   хранит ровно ту командную строку, что записал `adopt`; всё, что пользователь поменял после, —
   остаётся. Манифест хранит только командные строки (не `env`) и читается через схему.
7. Вывод проходит через редактор секретов: ключ в аргументе (`--token <значение>`, `--api-key=…`,
   пароль в URL) не печатается — вывод вставляют в issues и скриншоты. Имена серверов и пути — без
   управляющих символов: `.mcp.json` из чужого репозитория не перерисует таблицу пробного прогона.
8. Файл-симлинк (менеджер dotfiles или ссылка в клонированном проекте) показан в пробном прогоне
   вместе с файлом, куда ляжет запись.
9. Порядок `--apply`: проверка «не менялся» для всех файлов → копии и запись для отмены → замена
   файлов. Не удалось сохранить копии — не меняется ничего; не удалось записать один файл — запись
   для отмены сужается до записанных.

## Не делаем сейчас

VS Code (`mcp.json` с комментариями — JSONC) и Windsurf — после запуска, по запросам. Изменение
`.mcp.json` проекта затрагивает всех, кто его коммитит: вывод помечает эту область как «shared».

## Последствия

- Копии хранят конфиги целиком, с ключами из `env`, и ничто их не удаляет само: руководство говорит
  удалить `<data-dir>/adopt`, когда отмена больше не нужна.

- Политика для всех обёрнутых серверов — один файл `<data-dir>/policy.json` (четвёртый источник
  `wrap`, ADR-0005): Quick start шага Stop больше не перевыпускает каждый сервер с `--policy`.
- Порча конфига клиента — худший исход первой минуты; поэтому показ по умолчанию, копия, проверка
  «файл не менялся», атомарная замена и `--undo`.
