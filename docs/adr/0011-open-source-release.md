# ADR-0011: Открытый релиз под Apache-2.0 вместо пилотов с design-партнёрами

- **Статус**: принято (2026-09-03, решение владельца S3 по итогам security-аудита)
- **Область**: дорожная карта (M6 «Пилоты» и трек B), лицензия и файлы у корня
  (`LICENSE`, `NOTICE`, `SECURITY.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, поле `license` в
  `package.json`), состав публичного дерева, формулировки в README.

## Контекст

PRD строил валидацию гипотезы на 2–3 design-партнёрах, чей аудитор примет экспортированный
отчёт; ROADMAP держал контрольную точку «конец недели 8: нет партнёра → пивот». Трек B за
четыре недели дал: две публичные ветки на GitHub (один ответ — смежный вендор, дизайн-вход в M5),
два поста в LinkedIn без отклика (канал закрыт 19.08), один предметный комментарий в Threads без
квалификации, пять email-касаний 12.08 без ответов; follow-up 19.08 подготовлен, отправка в
pipeline не зафиксирована. Партнёра нет. Код при этом обогнал валидацию: M1–M5 и M5.5 закрыты,
сквозной security-аудит пройден (`docs/security-audit-2026-09.md`), 4533 теста.

Аудит поставил владельцу вопрос S3 — нужен ли независимый проход до первого партнёра. Ответ
владельца снял сам вопрос: писем больше не будет, партнёров не ищем, продукт выходит как открытый
код.

## Решение

1. **Лицензия — Apache License 2.0.** Разрешительная, с явной патентной лицензией; привычна
   enterprise-пользователям, которым продукт адресован. `LICENSE` — канонический текст
   (sha256 `cfc7749b…523d30`), `NOTICE` — имя проекта и правообладатель, `package.json` —
   `"license": "Apache-2.0"`.
2. **M6 «Пилоты» и трек B закрываются без исполнения.** Их место занимает «открытый релиз»:
   версия 0.1.0, `CHANGELOG.md`, `SECURITY.md` (приём уязвимостей через private vulnerability
   reporting GitHub, без почты в репозитории), `CONTRIBUTING.md` (правила: две прод-зависимости,
   TDD, инварианты, ADR, формулировки про журнал).
3. **Публичное дерево не содержит** `docs/pitch/` (имена и адреса реальных людей, черновики
   писем) и `.claude/` (внутренние планы, PRD, отчёты волн). ADR, смоки, аудит и дизайн-скриншоты
   остаются — это документация решений, а не переписка. Поскольку история приватного репозитория
   содержит эти файлы, **публичный репозиторий — это санированная копия с новой историей**, а не
   push приватного `main`; приватный репозиторий с полной историей и планами остаётся рабочим.
4. **Независимого security-прохода до релиза не будет.** Аудит остаётся внутренним и так и назван
   в README, SECURITY.md и самом отчёте; это честнее, чем ждать аудитора, которого не будет.
5. **Формулировки не меняются.** Журнал — «tamper-evident with an external anchor», без
   «tamper-proof» и «audit-ready». Открытый релиз не повод смягчать квалификатор.

## Последствия

- Строка PRD «сегмент — enterprise/compliance, валидация — design-партнёры» больше не
  описывает способ валидации: валидация теперь — использование открытого кода и обратная связь
  через issues. Позиционирование продукта («контроль доступа + доказательный журнал, не
  детекция и не generic gateway») остаётся.
- README перестаёт быть инструментом питча: таблица статуса остаётся источником истины о том,
  что есть, но ссылка на «pitch and landing material» уходит.
- Бэклог, отложенный «до данных пилотов» (индексная таблица агентов, 8-sink профиль, пауза SSE
  по `drain`, инструмент сверки якоря с `prune`), переходит в режим «по запросу пользователей».
- Публикация — отдельный шаг с явным согласием владельца: адрес репозитория, org, ветка.

## Когда пересматриваем

- Появится пользователь, готовый платить за поддержку или хостинг, — тогда отдельное решение о
  коммерческой модели (open-core, поддержка), не правка этого ADR.
- Кто-то из пользователей принесёт аудитора — S3 возвращается как «внешний проход по запросу».
