# Dogfood M2 — политики на собственных агентах

Gate выхода M2 (ROADMAP): «свои агенты работают через прокси с политиками;
изменяющий вызов не проходит без правила». Контрольная точка конца недели 4:
агенты живут через прокси ≥ 1 неделю; если approval fatigue невыносим —
политики-исключения до M4.

## Что развёрнуто (2026-08-05)

- `.mcp.json` проекта оборачивает два сервера в `mcp-journal wrap`:
  `@modelcontextprotocol/server-memory` (`--server memory`) и
  `@playwright/mcp` (`--server playwright`) — каждая новая сессия Claude
  Code в этом репозитории ходит к ним через прокси. Playwright добавлен как
  write-тяжёлый источник approval-fatigue-данных (клики/навигация/формы —
  почти всё не read). Внимание: плагиновые playwright-серверы (official и
  ecc) при этом остаются активными в обход прокси — для честного dogfood их
  стоит отключить в `/plugin` на время недели, иначе агент может уходить в
  неблокируемые дубли тулзов.
- Политика: `./.mcp-journal/policy.json` — read → allow, всё остальное →
  require-approval (60s, timeout → deny), карантин новых тулзов включён,
  `tools/list` фильтруется, журнал fail-closed.
- Сторы (журнал, карантин, одобрения) — в `~/.mcp-journal/`.

Операторские команды во втором терминале:

```
mcp-journal approvals list / approve <id> / deny <id>
mcp-journal quarantine list / approve <server> <tool>
mcp-journal sessions / show <sessionId>
```

## Смок при развёртывании (2026-08-05, все пункты пройдены вживую)

- Свежий сервер: все 9 тулзов ушли в карантин; вызов `read_graph` блокирован
  до одобрения карантина (`quarantine approve --all --server memory`).
- После карантина: `read_graph` (read) — allow за ~2 мс по
  `classDefaults.read`; `create_entities` (write) без правила — блок,
  timeout → синтетическая ошибка `-32002` с id заявки в тексте.
- Полный цикл: заявка → `approvals approve` из CLI → исходный вызов ушёл на
  сервер (~1.2 с), ответ дошёл до клиента; одобрение создало 5-минутный грант.
- Журнал: каждое решение записано с `outcome` и сработавшим правилом
  (`defaultDecision`, `classDefaults.read`, `toolsList.*`).

## Наблюдения (заполнять по ходу недели)

Формат: дата — что случилось — сколько одобрений/час — вывод.

- 2026-08-05 — развёртывание. Первичный карантин 9 тулзов за раз — норм для
  onboarding'а сервера, `--all --server` спасает; поштучно было бы больно.
- 2026-08-05 — заявка живёт 5 минут, но клиентский вызов ждёт только
  `approval.timeoutMs` (60s). Если оператор не успел — агенту нужен retry;
  текст ошибки это объясняет, но fatigue-риск: одобрение «в пустоту» после
  таймаута не применяется к уже упавшему вызову, нужен повторный вызов агента.
- 2026-08-12 — итог недели по журналу (`~/.mcp-journal/`, 602 записи;
  журнал общий — в него попали и сессии смоков M3/M4, что для gate «свои
  агенты живут через прокси» корректно): активные дни 05, 06, 10, 11, 12.08
  (07–09.08 — пауза, работа шла над кодом M4 без MCP-трафика). Решения:
  98 allow (из них авто-allow по `classDefaults.read` и грантам),
  33 заявки на одобрение — **все разрешены** (28 approved,
  1 denied-by-operator, 4 timeout), pending — 0; 4 deny по отзыву
  агента/отсутствию гранта (смок M3); карантин срабатывал 16 раз.
- 2026-08-12 — approval fatigue: пик 22 заявки/день (12.08, write-тяжёлая
  сессия playwright+memory), в среднем ~5–7/активный день. Терпимо:
  5-минутные гранты после approve гасят повторные заявки на тот же тулз,
  UI-очередь M4 с SSE убрала необходимость держать CLI-терминал. Реальный
  раздражитель — не количество, а 4 одобрения «в пустоту» после 60s-таймаута
  (наблюдение от 05.08 подтвердилось за неделю): одобрил — а вызов уже упал,
  нужен повтор от агента. Кандидат на UX-правку (например, авто-применение
  позднего approve к ретраю) — решить по данным пилотов.

## Критерии закрытия gate

- [x] ≥ 1 неделя работы агентов через прокси (2026-08-05 → 2026-08-12,
      подтверждено журналом: сессии во все активные дни недели)
- [x] Изменяющий вызов не проходит без правила (подтверждено смоком)
- [x] Заметки об approval fatigue собраны; решение: **политики-исключения
      до M4 не понадобились** — fatigue терпимый, M4 (UI-очередь) закрыт
      параллельно dogfood и снял основной операторский неудобняк

## Закрытие (2026-08-12)

Gate выполнен по всем трём критериям — **M2 закрыт**. Dogfood-обвязка
(`.mcp.json` с `wrap`, политика `./.mcp-journal/policy.json`) остаётся
включённой: она продолжает давать данные для открытого вопроса M5
«любое ли расширение surfaceDelta эскалирует класс» (ROADMAP, бэклог M3).
