## Стенд

```
SMOKE=<scratch>/smoke-m55 && mkdir -p "$SMOKE"
printf '{"mode":"alive","variant":"v1"}\n' > "$SMOKE/probe-control.json"
HOME="$SMOKE" node dist/cli.js ui --port 8095      # owner-токен печатается один раз

  --command "$(which node)" --args "$PWD/tests/fixtures/probe-server.mjs,$SMOKE/probe-control.json"
```

Ленивая проба в 11:28 — не дефект, а точное срабатывание порога: между CLI-пробой (09:09) и просмотром прошло 2ч19м.

## Находки и уроки прогона

1. **Пустой `spawnLog: ""` в контрол-файле роняет фикстуру** до ответа на initialize (`appendFileSync('')`) — картина неотличима от мёртвого сервера. Урок для будущих прогонов: `spawnLog` либо валидный путь, либо отсутствует.
2. **Повторный `--args` затирает предыдущий** (синтаксис — `--args a,b`): node исполнял контрол-JSON вместо скрипта → `unreachable`. Тултип с причиной («ended before answering initialize») сделал диагностику мгновенной — то есть фича диагностирует сама себя.
3. **CLI-`refresh` не пушит SSE в открытую вкладку UI** — событие живёт в процессе, запустившем пробу; стор общий, вкладка увидит свежий статус при следующем рендере/своей пробе. Кросс-процессного шедулера событий нет по дизайну (O2: никаких фоновых механизмов); зафиксировано как известное поведение.
4. Одобрение playwright-вызова из push-уведомления **не разрешило заявку** (обе остались pending и истекли) — дефект пути «approve из уведомления» *обвязки* (не плоскости); наблюдение для бэклога dogfood-контура.

## Не покрыто

- Firefox/WebKit-плечо (как и во всех прошлых смоках — открытый пункт бэклога).
- Визуальное наблюдение мигания (`dot-blink` на probing/активности): окно попало между одобрениями playwright-вызовов; классы и `prefers-reduced-motion` закреплены тестами (`tests/ui/servers-render.test.ts`), CSS-анимация та же, что у живого региона очереди.
- no-JS деградация глазами: контракт закреплён тестами (страница валидна, статусы из стора); в браузере без JS не прогонялось.
- `vault-refused`-ветка в UI (в CLI покрыта e2e и юнитами).
