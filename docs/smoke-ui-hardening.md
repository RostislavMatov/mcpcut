# Сценарий ручного смока — заход «укрепление UI + availability»

**Статус: НЕ ПРОЙДЕН** (сценарий подготовлен 2026-08-16, ветка `feat/ui-availability-hardening`).
Заполнять колонку «Факт» по ходу прогона; в конце — вердикт и раздел «Находки».

## Зачем этот смок обязателен

Урок M4 (`docs/smoke-m4.md`, находка 1): `Referrer-Policy: no-referrer` заставлял Chromium
сериализовать `Origin` у form-POST как `null`, который наш же Origin-скрининг отвергал — вход в UI
из любого Chromium был невозможен. **Ни один тест на `node:http`/`fetch`/curl эту связку не
эмулирует.** Текущий заход трогает ровно тот же класс поверхностей:

- `Origin` стал ОБЯЗАТЕЛЕН на каждом POST (форма, `fetch`, logout);
- имя сессионной cookie за TLS сменилось на `__Host-`-префиксное, и неprefixed больше не принимается;
- добавлен редирект анонимного `GET /`;
- добавлен маршрут `/favicon.ico` и `<link rel="icon">`;
- со страницы логина убран SSE-атрибут (проверяется только консолью браузера);
- у `servers/add` появился шаг подтверждения.

Автотесты покрывают контракт, браузер — реальность. Прогонять **в Chromium И в Firefox**: расхождение
M4 было именно браузероспецифичным.

## Стенд

Реальный `~/.mcp-journal` не трогать — подменять `HOME` на скретч-каталог, как в смоке M4.5:

```
export SMOKE=/tmp/smoke-ui-hardening
mkdir -p "$SMOKE"
npm run build
HOME=$SMOKE node dist/cli.js ui --port 8091
# токен owner печатается на stderr один раз — скопировать
```

Для части 5 (TLS-режим) нужен второй запуск за прокси, терминирующим TLS. Если прокси под рукой нет,
часть 5 можно выполнить в урезанном виде — см. примечание там.

## Часть 1 — вход и базовая навигация (Chromium, затем Firefox)

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | Открыть `http://127.0.0.1:8091/` **без сессии** | 303 → страница `/login`, а не голый 403 | |
| 2 | На `/login` открыть DevTools → Console | **пусто**: нет 403 от `/events` (раньше был) | |
| 3 | DevTools → Network, отфильтровать `events` | запроса к `/events` со страницы логина **нет вообще** | |
| 4 | Проверить вкладку браузера | видна иконка (не дефолтная «пустая страница») | |
| 5 | Network → `favicon.ico` | 200, `content-type: image/svg+xml`; при перезагрузке — 304 | |
| 6 | Ввести токен owner, отправить форму | 303 → `/`, страница одобрений отрисована | |
| 7 | Console после входа | нет ошибок; в Network есть открытый `/events` (тип `eventsource`) | |
| 8 | Application → Cookies | `mcp_admin_session`, `HttpOnly`, `SameSite=Strict`, `Path=/`, **без** `Secure` (плоский HTTP) | |
| 9 | Открыть `/journal` без сессии (приватное окно) | 403, **не** редирект — редирект только у `/` | |

## Часть 2 — `Origin` на POST (главный риск этого захода)

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | Нажать «Logout» в UI | 302 → `/login`, cookie очищена. **Если 403 — это регресс класса M4**, POST из браузера обязан нести `Origin` | |
| 2 | Снова войти; одобрить любую заявку кнопкой (создать заявку: см. часть 4) | действие проходит, карточка исчезает | |
| 3 | В Console: `fetch('/logout',{method:'POST',headers:{'x-csrf-token':document.querySelector('meta[name=csrf-token]').content}})` | 302/200 — `fetch` со страницы шлёт `Origin` сам | |
| 4 | `curl -X POST http://127.0.0.1:8091/login -H 'content-type: application/json' -d '{"token":"..."}'` | **403** — не-браузерный POST без `Origin` отвергается | |
| 5 | Тот же curl + `-H 'Origin: http://127.0.0.1:8091'` | 303 — заголовок присутствует и допустим | |
| 6 | `curl` с `-H 'Origin: https://evil.com'` | 403 | |

## Часть 3 — `servers/add` и интерстициал

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | `/servers` под owner, заполнить форму (`name: smoke`, `transport: stdio`, `command: node`, `args: server.js,--flag`) | НЕ редирект: страница подтверждения с точной командой и аргументами | |
| 2 | На странице подтверждения нажать «Cancel» | вернулись на `/servers`, сервер **не** зарегистрирован | |
| 3 | Повторить и нажать «Register it» | 303 → `/servers`, сервер в списке | |
| 4 | Повторить с `command: <script>alert(1)</script>` | интерстициал показывает текст экранированным, **алерта нет** | |
| 5 | Повторить с секретом в env (`X=ghp_abcdefghijklmnopqrstuvwxyz0123456789`) | 400 с подсказкой про вольт **до** интерстициала | |
| 6 | Зайти под `operator` и открыть `/servers` | формы добавления нет; прямой POST → 403 | |

## Часть 4 — живой SSE и одобрения

Создать заявку живым клиентом (как в смоке M3/M4.5): `wrap`/`connect` на реальный MCP-сервер с
политикой `write: require-approval`.

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | При открытой вкладке `/` вызвать write-тулз агентом | карточка появляется без перезагрузки (SSE), счётчик растёт | |
| 2 | Одобрить в UI | карточка исчезает, агент получает ответ | |
| 3 | Открыть 9+ вкладок UI под одним админом | 9-я и далее падают на поллинг (503 + `Retry-After` в Network), UI продолжает работать | |
| 4 | Из CLI: `HOME=$SMOKE node dist/cli.js admin rotate <имя>` при открытой вкладке | вкладка теряет стрим и получает отказ **за ~2 с**, не за 15 | |
| 5 | Счётчик на `/` при большой очереди (>500 заявок; можно скриптом) | «N of M pending (showing the oldest)» | |

## Часть 5 — режим за TLS (`--behind-tls`)

Запустить UI с `--behind-tls` за прокси, терминирующим TLS. **Без реального HTTPS часть 5 не даст
верного ответа**: `__Host-`-cookie браузер откажется принимать по HTTP, что выглядит как поломка
входа, но таковой не является. Если прокси нет — прогнать пункты 1–2 через `curl -i` и пометить
часть как «частично».

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | Войти через HTTPS-фронт | cookie называется `__Host-mcp_admin_session`, атрибуты `Secure; HttpOnly; SameSite=Strict; Path=/`, **без** `Domain` | |
| 2 | Заголовки любого ответа | присутствует `strict-transport-security` | |
| 3 | Подменить в DevTools имя cookie на `mcp_admin_session` (то же значение) | запросы получают 403 — неprefixed имя в TLS-режиме не принимается | |
| 4 | Тот же UI без `--behind-tls` | `strict-transport-security` **отсутствует**, имя cookie обычное | |

## Часть 6 — availability логина

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | Завести 8 viewer-учёток, залогинить каждую 8 раз (56 сессий) | все проходят | |
| 2 | 57-й вход viewer | 429 | |
| 3 | Вход owner сразу после | **303, вход проходит** — это и есть закрытый баг смока M4 | |
| 4 | 5 неверных токенов подряд с одного адреса | 429 для этого адреса | |
| 5 | Верный токен owner с того же адреса после этого | 429 (окно per-address ещё открыто) — ожидаемо, окно 60 с | |
| 6 | `HOME=$SMOKE node dist/cli.js ui --trusted-proxy-header x-forwarded-for` | на stderr предупреждение «безопасно, только если прокси перезаписывает заголовок» | |
| 7 | `--trusted-proxy-header 'x forwarded for'` | отказ старта с внятной ошибкой, порт не занят | |
