# Ручной смок M4 — acceptance-прогон admin UI из реального клиента

**Статус: не пройден** (протокол подготовлен 2026-08-11). Последний открытый пункт acceptance M4
(план `.claude/plans/admin-ui-approvals.plan.md`): gate-метрика — человек одобряет/отклоняет
write-операцию из UI, агент получает ответ до истечения `approval.timeoutMs`. Автоматизированный
аналог зелёный (`tests/e2e/m4-integration.test.ts`, 10 сценариев).

Стенд (по образцу смока M3): реестр `github` → npx server-github, ключ `vault:github-pat`;
политика с `require-approval` на классе `write`; агент `smoke-m4` c грантом, включающим
write-тулз (например `create_issue`); сниппет в локальном `.mcp.json` (гитом не трекается).

## Подготовка

```bash
npm run build
node dist/cli.js admin add alice --role owner        # токен печатается один раз — сохранить
node dist/cli.js admin add bob --role operator
node dist/cli.js admin add carol --role viewer
node dist/cli.js ui --port 8091                      # отдельный терминал; stdout молчит
```

## Часть 1 — gate-критерий (`connect`, живой клиент)

| # | Действие | Ожидание | Факт |
|---|---|---|---|
| 1 | Открыть `http://127.0.0.1:8091`, войти токеном `alice` | 303 → консоль; cookie `HttpOnly`; повторный вход по чужому/испорченному токену неотличим от несуществующего | ☐ |
| 2 | Из живой сессии агента вызвать write-тулз под `require-approval` | Заявка появляется в UI ≤ 2 с **без перезагрузки** (SSE); карточка показывает агента, сервер, тулз, класс, редактированные аргументы и отдельно остаток ожидания агента / грант-окна | ☐ |
| 3 | Нажать Approve до истечения ожидания | Агент получает реальный ответ сервера до своего таймаута; в журнале `approved` с `actor: ui` + имя админа; то же имя в `approvals list` | ☐ |
| 4 | Повторить вызов, нажать Deny | Агент получает ошибку с тем же id; ровно один исход; `denied-by-operator` в журнале | ☐ |
| 5 | Повторить вызов, одобрить из CLI, затем нажать Approve в UI на том же id | UI отвечает «уже разрешено» (не 500); резолюция первого входа сохраняется | ☐ |
| 6 | UI запущен, `serve` НЕ запущен — проверить шаги 2–3 | Всё работает: очередь файловая, UI не зависит от `serve` | ☐ |

## Гигиена после прогона

- Отозвать смок-агентов (`agent revoke …`), убрать сниппет из `.mcp.json`.
- Удалить смок-админов или ротировать токены (`admin remove` / `admin rotate`).
- Latency approve (шаг 3) записать сюда: цель ≤ 1.3 с накладных сверх реакции человека.
