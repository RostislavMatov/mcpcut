# Смок: страница журнала по `Journal.dc.html` (вкладки, период-пикер, фильтр по агенту)

**Статус: ПРОЙДЕН** (прогон 2026-08-28, ветка `feat/ui-mcpcut-redesign`).
Источник — экран `Journal.dc.html` дизайн-проекта `claude.ai/design/p/862ebc55-…` (+ импортируемый им `support.js`). Скриншоты — `docs/design/mcpcut/journal-*.png`.

**Чем прогоняли:** живой стенд на подменённом `HOME` (реальный `~/.mcp-journal` не тронут), UI на порту 8097; журнал засеян тремя сессиями за три разных дня (8 + 2 + 2 записи: решения с классами/исходами, `stderr`, `notification`, `request`/`response`, латентности от 63 мс до 30 001 мс) — данные повторяют витрину дизайна. Браузер — headless Chromium скриптом (playwright из npx-кеша + `executablePath`, см. память `browser-smoke-without-mcp-gate`), **в двух контекстах: с JavaScript и с полностью выключенным JavaScript**.

## Что перенесено из дизайна

| Элемент дизайна | Как сделано у нас |
|---|---|
| Вкладки `Sessions` / `Records` в шапке панели | ссылки `/journal` и `/journal?view=records`; `Records` — сквозной поток записей всех сессий (раньше сквозной вид открывался только текстовым поиском) |
| Строка фильтров одной лентой | `text · kind · direction · method · tool · agent · outcome · период · Filter` |
| Выпадашка агента (`agent · any`) | нативный `<select name="agent">` с рамкой-белой при выбранном значении; варианты — из реестра агентов, не из записей |
| Период-пикер (пресеты `24h/7d/30d`, календарь, `All`, `Done`) | `<details>` + ячейки-**submit-кнопки** формы (`pick`, `period`, `pmnav`, `close`); свёртка в `from`/`to` — на сервере |
| Штамп времени `Aug 27 26 09:02:11` | `shortTime()`; полный ISO остаётся в `title` |
| Сетка записи `Time · Message · State · Lat` (+ `Session` в сквозных видах) | та же, колонка `Lat` теперь **всегда** (в дизайне — `—` там, где нет замера), поэтому сетка не «прыгает» между страницами |
| Раскрытие записи с `rule` и payload, отступ под колонку `Message` | `<details class="jr-rec">`, `padding-left: 178px` |
| Подсветка `Unreadable > 0` | белым и жирным |

## Найдено и закрыто в ходе смока

**Ячейки календаря разъезжались за границу попапа.** `.filters button { padding: 8px 12px }` (специфичность 0,1,1) перебивал `.jr-day { padding: 0 }` (0,1,0) — день получал ширину 42.6 px вместо 30 px, и семь колонок не влезали в 262 px попапа: числа 8, 9, 16, 23, 30 висели справа от рамки. Закрыто добавлением предка `.jr-picker` ко всем правилам контролов пикера (0,2,x). Урок тот же, что с `details.drawer` в смоке карточки сервера: **классовое правило страницы не перебивает классовое правило формы — специфичность надо считать, а не предполагать.**

**`First`/`Last` в списке сессий были прижаты вправо.** Общее `.jr-row.jr-session .num { text-align: right }` цепляло и штампы времени; в дизайне справа только два счётчика. Закрыто позиционным правилом на 2-ю и 3-ю ячейки.

## Расхождения с дизайном (сознательные)

- **Выпадашка агента — нативный `<select>`, а не кастомный попап.** Дизайн рисует свой список, потому что в Claude Design нативный `select` не стилизуется; у нас та же коробка (2px рамка, каретка, белая при выборе), но нативный список — он работает без JS и с клавиатуры, и участвует в сабмите формы наравне с текстовыми полями (кастомный попап-ссылками терял бы набранный текст).
- **В строке фильтров списка сессий агента нет.** Дизайн держит его там и отвечает на него, пробегая по записям своего in-memory массива; на сервере это значило бы читать записи каждой сессии, чтобы нарисовать список. Список сессий сужается только тем, что знает строка сводки: id и промежуток активности.
- **Ссылка вкладки `Sessions` не несёт фильтров уровня записи** (`kind`, `tool`, `agent`, `outcome`). Список сессий их не применяет и не показывает — оставить их в URL значило бы объявить сужение, которого нет.
- **У вкладки `Records` нет пейджера.** Сквозной обход ограничен потолками (файлы/байты/дедлайн) и не имеет offset'а, так что «страница 2» была бы обещанием, которое читающий слой не выполняет. Вместо пейджера — счётчик `all sessions · N shown` и штатный баннер усечения.
- **Порядок сессий** — «последняя запись первой» по `lastSeq` (как и было); на стенде он совпал с порядком, в котором сессии засевались, а не с их датами.

## Что НЕ проверялось

- Firefox/WebKit — только Chromium (headless shell).
- Закрытие попапа кликом по фону и по `Escape`: в дизайне это делает JS-обработчик (`pointerdown`/`keydown`); у нас закрытие — `Done`, повторный клик по кнопке периода или любой сабмит формы.
- Поведение на узком экране (< 820 px) — правила есть, но глазами не смотрели.
